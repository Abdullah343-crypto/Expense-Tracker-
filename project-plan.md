## Risks and mitigation
1. Flutter/Android setup problems: run flutter doctor early, keep setup notes and seek lab support early.
2. Data loss/database errors: test CRUD operations and keep sample data for repeatable tests.
3. Camera permission/emulator limitations: test on a physical Android phone and handle permission denial gracefully.
4. Uneven contribution: assign named owners, track progress and review GitHub commits weekly.

## Working agreement
- Communicate progress in the group chat at least twice per week.
- Each member completes assigned work and commits using their own GitHub account.
- Use clear commit messages; discuss changes before overwriting others' work.
- Raise blockers early and review changes together.
